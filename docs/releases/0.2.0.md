SeerODBC 0.2.0 syncs the driver with everything seerdb's `PROTOCOL.md` learned since 0.1.0. That covers fetch/bind correctness across every tier, the object and LOB tails, and native network encryption against servers that require it. It also adds 18c and 26ai to the live-validated matrix.

### New features

- **Native network encryption against servers that *require* it** (26ai, AES256 + SHA256). Two fixes: SQL errors no longer kill the session, because the data-integrity keystreams are re-derived after a break/reset (#55); and multi-packet replies are reassembled, because encrypted fragments can fall a block short of the fragment size (#56).
- **Object and collection OUT / IN OUT binds**: new `seer_stmt_bind_object_out()`, and `seer_stmt_bind_set_inout()` now accepts object binds (#51).
- **PL/SQL package-level types**: records, nested tables and index-by tables bind as `PKG.TYPE` (#50).
- **XMLType and CLOB/BLOB attributes of SQL objects** (#39). **23ai BOOLEAN object attributes** read and bind correctly (#50).
- **Large LOB values in PL/SQL**: a CLOB/BLOB value over 32 KB bound to a PL/SQL parameter goes as a temporary LOB (12c+) (#49); those temporary LOBs are freed once no longer referenced (#54).
- **Large CLOB / BLOB through DML RETURNING** (#48). **Large native VECTOR / JSON binds** (#47).
- **Inline LOB fetch, opt-in**: `LOBINLINE=1` / `SeerConnParams.lob_inline` fetches CLOB/BLOB content in the rows instead of one round trip per value; about 17–20× faster for LOB-heavy results. Off by default because in that form an empty LOB reads as NULL (#53).
- **Describe before execute**: `SQLNumResultCols` / `SQLDescribeCol` work after `SQLPrepare`; core `seer_stmt_describe()` (#45).
- **Diagnostics**:
  - a PL/SQL object created with compilation errors returns `SQL_SUCCESS_WITH_INFO` (ORA-24344);
  - the native ORA number is exposed, plus the error offset (`SQL_DIAG_SEER_ERROR_OFFSET`, 19113);
  - VECTOR column dimensions and format are exposed (19114 / 19115) (#46).
- **Typed NULL binds**, **IN OUT input values**, and **RETURNING truncation reported as 01004** (#34, #35, #36).

### Fixes

- **Fetch correctness** (#32):
  - rows fetched inside an open transaction are no longer cut off after the first batch;
  - zero-length columns, UROWID and nested cursor columns are handled.
- **Bind encoding**: NULL typing, the 252-byte inline limit, and LONG-class value ordering (#34).
- **Execute robustness** (#35):
  - flush-out-binds on failing DML RETURNING;
  - no SIGPIPE on a closed connection;
  - statement-kind detection with leading comments / labels / `CALL`.
- **Session** (#37):
  - failed statements' cursors are closed;
  - RPA session-state pairs are parsed;
  - the real OS user is reported to the server.
- **JSON/OSON**: hashed and ordered field names, version-3 and compressed images (#38).
- **Oracle 12.1 (field version 7)** spoken correctly (#41). **Chunked values**: pre-12.1 skip width and long AUTH fields (#43).
- **9i**: status replies read by count, and PL/SQL IN OUT directions followed. All 9i checks are green (#40, #44).
- **LONG columns over 252 bytes on 12c+** no longer desync the row (#53).
- **No 30 s stall when a reply ends in an exactly fragment-sized packet**. 10g LOB reads hit this deterministically and returned NULL (#52).
- **CodeQL**: the 53 open alerts addressed (#27).

### Tooling

- `tests/odbc/run-matrix.sh` targets remote beds via env vars / `matrix.env`, and supports `--only` / `--skip` tier selection. It exits non-zero on failures and covers 9i, 10g, 11g, 18c, 21c, 23ai and 26ai (#33).
- Tree-wide clang-format with CI enforcement (#31). The live suites repeat failed checks on stderr so CI logs name them (#54).

### Validation status (honest)

- **Live, locally, full matrix green:**
  - **9i** (core-API tier)
  - **10g, 11g, 18c, 21c** (full ODBC suite)
  - **23ai**: this local server advertises the 26ai-level field version and is capped to fv24
  - **26ai with required native encryption** (79/0)
- **GitHub CI** (public tier): **11g, 21c** and a genuine **23.x** image.
- **12.1 / 12.2 / 19c:** not validated against real servers. The 12.1 wire level is exercised by capping a 21c session at fv7. Expected to work, not proven.
- **8i:** not supported (a distinct older protocol dialect).
- **Sanitizers:** the new paths ran clean under AddressSanitizer on 21c/23ai.
- **Known flake:** the 23ai CI job failed once on #54 and passed on re-run; the cause was not identified and it has not recurred.
